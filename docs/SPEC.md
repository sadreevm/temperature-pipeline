# ТЗ. Сбор и выгрузка показаний датчиков температуры

## 1. Результат

Консольная программа на Python принимает файлы от двух вымышленных датчиков, переводит показания в общую схему, сохраняет их в SQLite и формирует дневной отчёт в CSV. Отдельная команда создаёт синтетические пакеты обоих форматов для проверки всего процесса.

Достаточно Python 3.11+, SQLite из стандартной библиотеки и тестов на `unittest`. Программа запускается из корня репозитория. Рабочий интерфейс — команды из раздела 5. Внутреннее устройство программы после первого этапа можно выбрать самостоятельно.

## 2. Входные форматы

Оба формата используют UTF-8. Идентификатор датчика — непустая строка без пробелов по краям. Время измерения — UTC в виде `YYYY-MM-DDTHH:MM:SSZ`. Дата и время должны существовать, поэтому, например, 30 февраля — ошибка.

**Датчик A, JSON.** Входной файл содержит один объект. `temperature` — конечное JSON-число в градусах Цельсия. Строки, логические значения и `null` недопустимы.

`tests/fixtures/sensor_a.json`:

```json
{"device_id": "temp-01", "timestamp": "2026-11-10T09:30:00Z", "temperature": 36.7}
```

**Датчик B, CSV.** Первая строка — заголовок ровно в указанном порядке. Далее идёт одна или несколько строк данных. `temp_tenths` — целое число в десятых долях градуса Цельсия. Например, `367` означает 36.7 °C, а `-25` означает −2.5 °C.

`tests/fixtures/sensor_b.csv`:

```csv
serial,recorded_at,temp_tenths
temp-01,2026-11-10T09:30:00Z,367
temp-01,2026-11-10T10:30:00Z,373
temp-02,2026-11-11T00:00:00Z,-25
```

Оба разборщика приводят показания к одной записи:

| Поле | Тип | Значение для первого показания |
| --- | --- | --- |
| `sensor_id` | `str` | `temp-01` |
| `measured_at` | `str` | `2026-11-10T09:30:00Z` |
| `temperature_c` | `float` | `36.7` |

У JSON обязательны три указанных поля, дополнительные поля можно игнорировать. CSV с неверным заголовком, строкой с неправильным количеством полей или без строк данных считается ошибочным. На уровне разборщика ошибка входных данных поднимает `ValueError`. В сообщении укажи поле, если ошибка в поле, и номер строки файла, если ошибка в строке CSV.

## 3. Хранение

Таблица `measurements` хранит три поля общей записи. Первичный ключ — пара `(sensor_id, measured_at)`. Один датчик может прислать одно и то же измерение в двух форматах. Повторный импорт такого пакета оставляет одну запись. Если температура для того же ключа изменилась, последнее успешно импортированное значение заменяет старое.

Один входной файл импортируется целиком. Если в файле есть ошибка, ни одно показание из него не добавляется и ни одна существующая запись не меняется. При первом импорте программа создаёт таблицу при необходимости.

## 4. Дневная выгрузка

Группировка выполняется SQL-запросом по дате UTC и датчику. Отчёт включает все дни, для которых есть измерения. Строки сортируются сначала по дате, затем по идентификатору. Температуры выводятся с двумя знаками после точки. Если таблица пуста, выгрузка содержит только заголовок.

После импорта обоих файлов из раздела 2 содержимое отчёта должно быть таким:

```csv
day,sensor_id,count,min_c,max_c,avg_c
2026-11-10,temp-01,2,36.70,37.30,37.00
2026-11-11,temp-02,1,-2.50,-2.50,-2.50
```

## 5. Команды

Предлагаемая точка входа — `main.py`. Запуск с `--help` показывает доступные команды и аргументы.

```bash
python main.py import --format json --input tests/fixtures/sensor_a.json --db demo.sqlite
python main.py import --format csv --input tests/fixtures/sensor_b.csv --db demo.sqlite
python main.py report --db demo.sqlite --output daily.csv
python main.py generate --out-dir demo_packets --date 2026-11-10 --count 3 --seed 42
python -m unittest discover -s tests -v
```

- `import` принимает один файл. При ошибке входных данных завершает работу с ненулевым кодом и пишет в stderr имя файла и причину.
- `report` создаёт или перезаписывает указанный CSV в UTF-8. Если базы или таблицы нет, команда сообщает об ошибке и завершается с ненулевым кодом.
- `generate` создаёт выходную папку при необходимости. Дата — день UTC. `--count` принимает целое число от 1 до 1440 и задаёт количество показаний **на датчик**. Первое показание приходится на 00:00 UTC, следующие идут с интервалом в минуту. Команда создаёт `a_001.json`, `a_002.json` и так далее для датчика `demo-a`, а также один файл `b.csv` с показаниями датчика `demo-b`. При одинаковых аргументах результат воспроизводится. Генератор создаёт валидные пакеты, а ошибки проверяются отдельными тестами.

## 6. Порядок работы и критерии готовности

1. **JSON.** Создай `parsers.py` и функцию `parse_json_packet(raw: str)`. Она принимает содержимое файла и возвращает словарь по общей схеме. Начни с двух тестов: сохранённый пакет даёт ожидаемый словарь, а отсутствие `temperature` приводит к `ValueError` с именем поля. Затем добавь проверку неверного типа температуры и некорректной даты.
2. **CSV.** Добавь разбор второго формата. Проверь, что первая строка данных из CSV и сохранённый JSON дают одинаковую запись, отрицательная температура преобразуется правильно, а неправильное целое число даёт ошибку с номером строки.
3. **SQLite и импорт.** Проверь на временной базе повторный импорт одного файла и замену температуры для существующего ключа. Отдельно проверь CSV с корректной первой строкой данных и ошибкой во второй. Содержимое таблицы после такого импорта совпадает с исходным.
4. **Отчёт.** Импортируй оба сохранённых файла в новую базу. Проверь заголовок, порядок строк и все значения отчёта по примеру из раздела 4.
5. **Генератор.** Дважды запусти его с одинаковыми аргументами в разные папки и сравни файлы. Импортируй три сгенерированных JSON и один CSV в новую базу. В отчёте ожидаются две строки за 10 ноября 2026 года с тремя измерениями у каждого датчика.
6. **Подготовка к показу.** В `README.md` опиши назначение проекта, требования к запуску, команды из раздела 5 и ожидаемый отчёт. Проверь запуск по инструкции из свежей копии. Сохраняй коммиты по завершённым шагам. В репозиторий включи сохранённые тестовые пакеты, а локальную базу и результаты демонстрационных запусков добавь в `.gitignore`.

Для собеседования сохрани один реальный пример работы с агентом: какой результат ты запросил, как проверил изменения и каким тестом или запуском подтвердил поведение.
